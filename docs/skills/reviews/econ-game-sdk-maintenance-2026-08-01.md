## Scope and repeat evidence

The workflow maintains the typed internal client for already implemented HTTP routes. It is repeatable because two independent Node consumers currently duplicate HTTP route usage: `services/frontend/pages/pos.tsx` / `kds.tsx` and `services/bot/src/commands/ops.ts` / `pos.ts` / `kds.ts`. The package also separates the existing Python preview route family instead of merging incompatible shapes.

It excludes future product endpoints, Architecture decisions, service implementation, Prisma models, database state, migrations, deployment, identity, money semantics, authorization, and retry/idempotency policy.

## Safety boundary

- [x] No `.env`, secret, token, connection string, or personal data is read or written.
- [x] No database connection, service startup, migration, `db push`, deployment, formatter, or destructive command is the default.
- [x] The source check reads only route source files; package tests use mock fetch.
- [x] Mutating client methods have no automatic retry; demo bootstrap requires a confirmation token.
- [x] Python preview is explicitly isolated and does not imply adoption or migration.
